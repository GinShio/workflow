這份文件回答「配置已經裝好了，接下來怎麼用」。實作理由仍在 =config.org= 與
=org/*.org=；這裏只整理入口、工作流、模式鍵與上游手冊。

* 先學會發現功能

這份配置清空的是 *全域* keymap，沒有清空 major mode 與 minor mode 的 map。也就是說：

- 自己的跨模式命令都從 leader ~M-m~ 進入。
- 某個模式自己的命令仍然留在 =C-c=、單鍵或 mode-local 前綴下。
- 引入一個包，不等於要把它的全部命令重新綁一次；先用 Emacs 的自省能力讀它。

| 入口       | 用途                                                        |
|------------+-------------------------------------------------------------|
| ~M-m~        | 打開 leader；停 0.5 秒，which-key 顯示下一層                 |
| ~M-m SPC~    | 執行任意命令，等同 ~M-x~                                     |
| ~M-m h m~    | ~describe-mode~：當前 major/minor mode、模式鍵與說明          |
| ~M-m h k~    | ~describe-key~：按一個鍵，查看它在此處實際解析成什麼          |
| ~M-m h f~    | ~describe-function~：函數文檔、定義位置、來源文件             |
| ~M-m h v~    | ~describe-variable~：變量文檔、當前值、custom group          |
| ~M-m h b~    | ~describe-bindings~：列出當前緩衝區所有有效鍵位               |
| ~M-m h a~    | ~apropos-command~：按名字或概念搜索命令                       |
| ~M-m h i~    | 打開 Info                                                     |
| ~M-m h r~    | 打開 GNU Emacs manual                                        |
| ~M-m f g~    | 打開本指南                                                    |
| ~M-m f p~    | 打開文學配置源碼                                              |

按了 leader 後 which-key 顯示的是這份配置的樹；進入 Dired、Magit、Dape、Markdown 等
模式後，~M-m h m~ 顯示的是該模式自己的完整接口。兩者合起來纔是全部功能。

上游基礎文檔：[[info:emacs#Key Bindings][Emacs: Key Bindings]]、[[info:elisp#Keymaps][Elisp: Keymaps]]、
[[https://github.com/justbur/emacs-which-key][which-key README]]。

* 安裝、同步、清理與診斷

普通 Emacs 是套件 *消費者*。它只讀 =straight.lock= 與 =sync= 留下的 activation 快照；
缺任何一項就中止，不嘗試聯網修復。反過來，維護進程也不載入配置：它把
=modules/ginshio/*.el= 當資料讀，取出 ~:straight~ 宣告，一行配置代碼都不執行。

| shell 命令                     | 何時使用                                              |
|--------------------------------+-------------------------------------------------------|
| =bin/ginshio-emacs sync=         | 第一次安裝，或改過宣告／拉到新 lock 之後              |
| =bin/ginshio-emacs upgrade=      | 主動接受上游新 revision，重建動過的包並更新 lock      |
| =bin/ginshio-emacs rebuild=      | 某個包裝了卻不完整，或懷疑構建與源碼不同步            |
| =bin/ginshio-emacs clean=        | 丟棄 tangle、構建與快照，但留着 clone                 |
| =bin/ginshio-emacs cleanall=     | 連 clone 一起丟                                       |
| =bin/ginshio-emacs doctor=       | 配置能啓動，但某個外部功能不工作時                    |

=sync= 在無事可做時不聯網也不輸出：它先比對每個倉庫的 HEAD 與鎖，對得上就什麼都不做。
所以「改了一行配置」與「什麼都沒改」兩種情況的代價差不多，可以隨手跑。

=rebuild= 的症狀識別：某個包的命令報 =Cannot open load file=，或者一個模式明明裝了卻少
一半功能，而 =sync= 跑完什麼都沒說。那表示 build 目錄不完整，而 =sync= 信任了 build
cache。它不改 =straight.lock=，也不聯網取新 revision，但它走 straight 完整的規範化
checkout，所以跑偏的分支與 remote 也一併修正。

*換過 Emacs 版本不需要 =rebuild=。* 構建目錄與快照按版本分家，新版本的 build cache 是空
的，=sync= 自然全建；切回舊版本也不用重建。

=clean= 與 =cleanall= 的差別只有一個：要不要重新下載。=clean= 刪
=modules/ginshio/=、=$XDG_DATA_HOME/emacs/straight/build*=、
=$XDG_DATA_HOME/emacs/activation*= 與 =$XDG_CACHE_HOME/emacs/eln-cache/=，保留
=straight/repos/=——之後的 =sync= 純本地恢復。=cleanall= 連 =repos/= 一起刪。

文學源碼、=early-init.el=、=init.el=、=straight.lock=、=maintain.el=、=modules/= 下受版本
控制的上游 modes 與資產、書籤、歷史、grammar、auto-save 與 backup 都保留。先由
system/service 停止所有使用這份配置的 Emacs 再清理；腳本不探測或管理 daemon。執行後不要
直接開 Emacs：普通啟動會按契約失敗，下一步應是 =bin/ginshio-emacs sync=。

要不改動任何東西地查看套件樹，直接用 =maintain.el= 的內部函數：

#+begin_src shell
emacs -Q --batch --init-directory="$PWD" \
  --eval '(setq ginshio-maintain-auto-run nil)' \
  -l maintain.el \
  --eval '(progn (ginshio-maintain--load-straight)
                 (setq ginshio-maintain--declarations (ginshio-maintain--collect))
                 (ginshio-maintain--resolve nil)
                 (pp (ginshio-maintain--revisions)))'
#+end_src

fetch、update、merge、rebuild、delete、write-lock 一律在維護進程執行，不會在運行中的編輯
器裏偷偷改套件樹。

手冊：[[https://github.com/radian-software/straight.el][straight README]]、[[file:org/05-packages.org][本配置的 package lifecycle]]。

** XDG 目錄

| 變量               | 這份配置放什麼                                  |
|--------------------+-------------------------------------------------|
| =XDG_CONFIG_HOME=    | auth source 等真正的配置資料                    |
| =XDG_DATA_HOME=      | 套件 source/build、書籤、縮寫                   |
| =XDG_STATE_HOME=     | 歷史、最近文件、位置、項目、layout、斷點        |
| =XDG_CACHE_HOME=     | 備份、自動保存、native compilation、TRAMP cache |
| =XDG_RUNTIME_DIR=    | 本機 Emacs server socket                        |

五個變量都必須存在且是絕對路徑；runtime 必須已存在、可寫、權限 =0700=。其餘
=…/emacs/= 子目錄由配置建立並收緊成 =0700=。

* Server 與啓動

** 默認 server

配置本身同時兼容普通圖形 Emacs 與 daemon；=bin/ginshio-emacs= 不包裝它們。普通圖形 Emacs
啓動後會自動開 server，daemon 則應由 system/service 管理。

絕大多數時候只用 Emacs 的默認名字 =server=。daemon service 的底層命令與日常客戶端可以
直接使用 Emacs 原生接口：

#+begin_src shell
emacs --init-directory=/path/to/emacs-next --fg-daemon
emacsclient -c
#+end_src

不指定名字時，=server-name= 保持 Emacs 的默認值，所以裸 =emacsclient=、Git 的
=emacsclient= 與桌面啓動器都沿用 Emacs 原本的行為。

** 多 server

需要隔離另一套 daemon 時才顯式命名：

#+begin_src shell
emacs --init-directory=/path/to/emacs-next --fg-daemon=work
emacsclient -s work -c
GINSHIO_SERVER_NAME=scratch emacs --init-directory=/path/to/emacs-next
#+end_src

daemon 名由 ~--daemon=NAME~ / ~--fg-daemon=NAME~ 帶入；=GINSHIO_SERVER_NAME= 只用於讓普通
圖形 Emacs 顯式成為另一個具名 server。不要把它全局設成非默認值，否則普通 Emacs 也會
離開日常使用的默認 =server=。

** 啓動畫面與 initial-buffer-choice

沒有文件要打開時顯示 dashboard；命令行已要求打開文件時，那個文件直接佔滿 frame，不先
插入 dashboard 造成分屏。空的 emacsclient frame 仍顯示 dashboard。

dashboard 的 =r=、=p=、=m= 分別進入最近文件、項目、書籤；在 dashboard 裏先用
~M-m h m~ 查看它完整的 mode-local 鍵位。上游文檔：
[[https://github.com/emacs-dashboard/emacs-dashboard][emacs-dashboard README]]。

* 選擇、搜索與補全

** Minibuffer

Vertico 只改候選項的呈現；Orderless 決定匹配；Marginalia 添加註解；Consult 提供候選
來源；Embark 對候選項執行動作。

Orderless 用空格分片且順序無關。例如輸入 =key el= 可以匹配 =ginshio-keys.el=。文件名
類別保留 =basic= / =partial-completion=，所以 =~/=、環境變量與 TRAMP 路徑仍按 Emacs 的
文件規則工作。

Vertico 會話裏：

| 鍵              | 用途                                      |
|-----------------+-------------------------------------------|
| ~C-n~ / ~C-p~     | 下一個 / 上一個候選項                     |
| ~M-v~ / ~C-v~     | 上一頁 / 下一頁                           |
| ~RET~             | 接受候選項                                |
| ~TAB~             | 把候選項插入 minibuffer，繼續補全         |
| ~M-RET~           | 接受當前原始輸入，不強制選候選項          |
| 文件補全中 ~DEL~ | 按目錄層級向上刪                          |
| 文件補全中 ~M-DEL~ | 刪除上一段路徑                          |
| ~M-r~             | 用 Consult 選擇 minibuffer 歷史           |

常用 Consult 入口：

| 鍵         | 用途                                               |
|------------+----------------------------------------------------|
| ~M-m b b~    | 當前項目的緩衝區；不在項目中則顯示全域來源       |
| ~M-m b B~    | 全域 buffer、最近文件、書籤、項目來源            |
| ~M-m s s~    | 當前緩衝區全部匹配                               |
| ~M-m s S~    | 多個緩衝區全部匹配                               |
| ~M-m s g~    | ripgrep；默認從項目根開始                        |
| ~M-m s G~    | git grep                                          |
| ~M-m s f~    | fd 按文件名尋找                                  |
| ~M-m s i~    | 當前緩衝區 imenu                                 |
| ~M-m s I~    | 多緩衝區 imenu                                   |
| ~M-m s m~    | mark ring                                         |
| ~M-m f r~    | 最近文件                                         |
| ~M-m i y~    | kill ring                                         |
| ~M-m i r~ / ~i s~ | 跳到 / 儲存 register                         |

跨文件命令不自動預覽；在候選項上按 ~M-.~ 才預覽。Consult 提示中按 =<= 進入 narrow，
可用來源字母會顯示在列表中。給 =s g=、=s f= 等命令前綴參數時會先詢問目錄。

上游文檔：[[https://github.com/minad/vertico][Vertico]]、[[info:orderless#Top][Orderless]]、
[[https://github.com/minad/marginalia][Marginalia]]、[[https://github.com/minad/consult][Consult]]。

** Embark 與批量修改搜索結果

在 minibuffer 候選項或普通緩衝區中的文件名、URL、符號上按 ~M-m .~：

| 動作鍵 | 用途                                      |
|--------+-------------------------------------------|
| =w=      | 複製候選項                               |
| =i=      | 插入候選項                               |
| =E=      | export 成對應的專用緩衝區               |
| =S=      | snapshot 成 Embark Collect 緩衝區       |
| =SPC=    | 選中多個候選項，之後可一次對全部操作    |
| =A=      | 對全部候選項執行動作                     |

批量改 grep 結果：

1. ~M-m s g~ 搜索。
2. ~M-m . E~ 導出成 grep 緩衝區。
3. ~C-c C-p~ 進入 wgrep 可編輯狀態。
4. 像普通文本一樣修改；~C-c C-d~ 標記刪除整行匹配。
5. ~C-c C-c~ 或 ~C-x C-s~ 寫回原文件；~C-c C-k~ 放棄。
6. ~C-x C-q~ 離開 wgrep。

手冊：[[info:embark#Top][Embark]]、[[https://github.com/mhayashi1120/Emacs-wgrep][wgrep README]]。

** 緩衝區內補全

Corfu 自動在輸入兩個字符後彈出，候選項由 Eglot、major mode 與 Cape 共同提供：

| 鍵          | 用途                                      |
|-------------+-------------------------------------------|
| ~C-n~ / ~C-p~ | 下一個 / 上一個候選項                   |
| ~RET~         | 插入候選項                              |
| ~TAB~         | 繼續補全或完成共同前綴                  |
| ~M-TAB~       | 展開候選項                              |
| ~M-SPC~       | 插入 Orderless 分隔符                   |
| ~M-h~         | 候選項文檔                              |
| ~M-g~         | 候選項定義位置                          |
| ~C-g~         | 關閉 popup                              |

圖形 frame 使用 child frame；TTY frame 由 corfu-terminal 畫 popup。同一 daemon 混用 GUI
與終端不需切換模式。手動觸發仍是 major mode 的 ~completion-at-point~；可用
~M-x completion-at-point~。

語言服務器的候選項可以帶參數：選中 ~emplace_back~ 之後插入的是
~emplace_back(Args&&... args)~，光標落在第一個參數上，~TAB~ 跳到下一個，~S-TAB~ 回上一
個。展開由 yasnippet 負責，但這份配置一個 snippet 都不放——模板全部由服務器供給，所以
沒有觸發詞要記，也沒有模板庫要維護。理由見 [[file:org/55-lsp.org][lsp 模塊]]。

上游文檔：[[https://github.com/minad/corfu][Corfu]]、[[https://github.com/minad/cape][Cape]]、
[[https://codeberg.org/akib/emacs-corfu-terminal][corfu-terminal]]。

* 窗口、項目與 layout

一個項目對應一個 tab，但 tab-bar 故意隱藏。tab 是工作區實作，不是需要直接操作的 UI。

|----------------------------+---------------------------------------|
| ~M-m w w~                    | 下一個窗口                            |
| ~M-m w b/n/p/f~              | 左 / 下 / 上 / 右窗口                 |
| ~M-m w B/N/P/F~              | 與左 / 下 / 上 / 右窗口交換內容       |
| ~M-m w 1~ … ~w 9~            | 按 modeline 顯示的編號直達窗口        |
| ~M-m w v~ / ~w s~            | 垂直 / 水平分割                       |
| ~M-m w k~ / ~w K~            | 刪當前 / 刪其他窗口                   |
| ~M-m w =~                    | 平衡窗口                              |
| ~M-m w z~                    | 顯示或隱藏 side windows               |
| ~M-m w u~ / ~w r~            | layout 歷史後退 / 前進                |
| ~M-m w l s~ / ~r~ / ~k~      | 保存 / 恢復 / 忘記具名 layout        |
| ~M-m p p~                    | 選項目；通常切到它自己的 tab          |
| ~M-m p P~                    | 在當前 tab 臨時切項目                 |
| ~M-m p d~                    | 項目根 Dired                          |
| ~M-m p c~                    | 項目編譯；默認 =wits build=             |
| ~M-m p r~                    | 項目範圍正則替換                      |
| ~M-m p k~                    | 關閉項目及其緩衝區                    |
| ~M-m p ]~ / ~p [~            | 下一個 / 上一個項目 tab               |
| ~M-m p u~                    | 恢復剛關閉的項目 tab                  |

Help、Info、Eldoc 等短讀緩衝區去右側 side window；compile、grep、xref、Flymake、Messages
等持續觀察的輸出去底部且不搶焦點。~M-m w z~ 可以暫時收起全部 side windows。

~M-m p c~ 在項目根執行可編輯的 ~compile-command~。默認只寫 =wits build=：項目、focus、
branch、worktree 與 CMake/Meson/Cargo backend 都由 Wits 從當前根目錄解析，Emacs 不另存
一份容易過期的 identity。未註冊目錄或 detached HEAD 會顯示 Wits 的原始錯誤；項目的
=.dir-locals.el= 可以覆蓋命令。

手冊：[[info:emacs#Windows][Emacs: Windows]]、[[info:emacs#Projects][Emacs: Projects]]、
[[info:emacs#Tab Bars][Emacs: Tab Bars]]、[[https://github.com/deb0ch/emacs-winum][winum]]；配置細節見
[[file:org/10-window.org][window 模塊]]。

* 編輯、撤銷與多光標

~C-_~ 撤銷，~M-_~ 重做。撤銷歷史由 undo-fu-session 存在 state 目錄，關閉再打開文件仍可
繼續撤銷；保存時 ws-butler 只清理你改過行尾的多餘空白。

| 鍵                    | 用途                                  |
|-----------------------+---------------------------------------|
| ~M-m e r~               | 矩形選區                              |
| ~M-m e f f~             | fill paragraph                        |
| ~M-m e f c~             | 設定 fill-column                      |
| ~M-m e l~               | 選區每一行一個光標                    |
| ~M-m e b~ / ~e e~       | 每行行首 / 行尾一個光標               |
| ~M-m e n~ / ~e p~       | 下一個 / 上一個相同文本               |
| ~M-m e N~ / ~e P~       | 跳過此處，選下一個 / 上一個           |
| ~M-m e u~ / ~e U~       | 收回下一個 / 上一個光標               |
| ~M-m e m~               | 進入 extended 選擇，用方向鍵加減      |
| ~M-m e a~ / ~e A~       | 智能標全部 / 標全部相同文本           |
| ~M-m e #~               | 每個光標插入遞增數字                  |
| ~M-m e s~ / ~e v~       | 排序 / 反轉各區域                     |
| ~C-S-鼠標左鍵~          | 在點擊處切換額外光標                  |

多光標裏 ~RET~ 結束，~C-g~ 結束並回到原始光標。第一次執行某些命令時 multiple-cursors 會
詢問是否對所有光標執行，答案持久化在 =mc-lists.el=。

文檔：[[https://github.com/magnars/multiple-cursors.el][multiple-cursors README]]、

* 外部命令、終端與遠程

** Shell 與 Eat

| 鍵         | 用途                                              |
|------------+---------------------------------------------------|
| ~M-m ! !~    | 同步跑一條 shell command，輸出進緩衝區            |

** Dape

最短工作流：

1. 在想停的位置 ~M-m d b~。
2. ~M-m d d~ 選配置並啓動。
3. ~M-m d n~ 單步越過，~d i~ 步入，~d o~ 步出，~d c~ 繼續。
4. ~M-m d v~ 臨時求值，~d w~ 加入 watch，~d ?~ 打開資訊面板。
5. ~M-m d q~ 結束；~d Q~ 連被調試程序一起殺掉。

| 鍵                         | 用途                               |
|----------------------------+------------------------------------|
| ~M-m d b~ / ~d B~           | 切換斷點 / 刪除全部斷點           |
| ~M-m d e~ / ~d h~ / ~d l~   | 條件 / hit count / log breakpoint |
| ~M-m d p~ / ~d r~           | pause / restart                    |
| ~M-m d u~                    | 運行到光標行                       |
| ~M-m d m~ / ~d a~           | memory / disassembly               |
| ~M-m d R~                    | REPL                               |
| ~M-m d s~ / ~d t~           | 選 stack frame / thread            |

固定配置寫進項目 =.dir-locals.el= 的 ~dape-command~；配置例與完整流程在
[[file:org/55-dap.org][dap 模塊]]。上游文檔：[[https://elpa.gnu.org/packages/dape.html][GNU ELPA: Dape]]。

* LLVM IR、MIR、MLIR 與 TableGen

這四類文件使用 llvm-project 隨上游維護的 major modes；它們以同一個固定 release tag
保存在 =modules/llvm/= 與 =modules/mlir/=，不經套件管理器另取互相漂移的版本。

| 文件                         | major mode        |
|------------------------------+-------------------|
| =.ll=、=.lgc=                  | ~llvm-mode~         |
| =.mir=                         | ~llvm-mir-mode~     |
| =.mlir=                        | ~mlir-mode~         |
| =.td=                          | ~tablegen-mode~     |

第一版只提供文件識別與上游模式的文本編輯能力，不自動啓動 LSP，也不配置 LLVM/MLIR
命令行工具。進入文件後用 ~M-m h m~ 查看模式說明與局部鍵位；來源、固定版本與引入理由見
[[file:org/68-lang-llvm.org][lang-llvm 模塊]]。

* 版本控制

日常提交、分支與 rebase 仍以終端 Git 為主；Emacs 負責文件旁的差異、歷史追蹤、選行暫存、
Git 叫出的編輯器、衝突解決，以及 Git 自己那幾種配置文件。

| 鍵                    | 用途                                  |
|-----------------------+---------------------------------------|
| ~M-m g d~ / ~g D~       | 當前文件 / 整個倉庫 diff             |
| ~M-m g l~ / ~g L~       | 文件 / 倉庫 log                      |
| ~M-m g b~               | annotate / blame                      |
| ~M-m g h~               | 選中行的歷史                         |
| ~M-m g f~               | 打開另一 revision                    |
| ~M-m g s~               | vc-dir                               |
| ~M-m g r~               | 刷新 VC 與 diff-hl                   |
| ~M-m g n~ / ~g p~       | 下一個 / 上一個 hunk                 |
| ~M-m g v~               | 顯示 hunk                            |
| ~M-m g a~               | 暫存當前 hunk 或選區                 |
| ~M-m g x~               | 還原當前 hunk                        |
| ~M-m g i~               | 插入忽略規則，可一次選多個主題       |

~M-m g i~ 從 =modules/gitignore/= 讀一份離線的規則清單，逗號分隔可以一次選多個主題
（=C++,CMake,Linux,Emacs=），插在 point 處。它不要求當前緩衝區是 =.gitignore=，所以往
一份已有的清單裏補一段也走同一個鍵。清單的來源、各自的 revision 與本地追加見該目錄的
=README=。

=.gitignore=、=.gitattributes=、=.gitconfig= 與 =.gitmodules= 由 git-modes 提供 major
mode。=.gitattributes= 那個最值得知道：光標停在一個 attribute 上，eldoc 直接說明它做什
麼，~M-C-f~ / ~M-C-b~ 逐個 field 移動，~M-x gitattributes-mode-help~ 開
=gitattributes(5)=。

衝突：

| 鍵                         | 用途                         |
|----------------------------+------------------------------|
| ~M-m g c n~ / ~g c p~       | 下一個 / 上一個衝突         |
| ~M-m g c u~ / ~g c l~       | 保留 upper / lower          |
| ~M-m g c b~                 | 保留 base                   |
| ~M-m g c a~ / ~g c c~       | 保留全部 / 當前             |
| ~M-m g c r~                 | 智能 resolve                |
| ~M-m g c e~                 | 交給 Ediff                  |

Git 用 emacsclient 打開提交信息或 rebase todo 時，緩衝區獨佔 frame；完成後 with-editor 還原
原 layout。提交信息用 ~C-c C-c~ 完成、~C-c C-k~ 取消。rebase todo 的單鍵表與 mergetool
流程在 [[file:org/45-vc.org][vc 模塊]] 有完整表格。

手冊：[[info:emacs#Version Control][Emacs VC]]、[[info:magit#Top][Magit]]、
[[info:ediff#Top][Ediff]]、[[https://github.com/dgutov/diff-hl][diff-hl]]。

* LaTeX

=.tex= 文件由 AUCTeX 打開，CDLaTeX 疊在上面提供快速環境與數學輸入。默認引擎是
LuaLaTeX，構建命令是 AUCTeX 內建的 LaTeXMk；文檔或目錄局部變量可以覆蓋兩者。

| 鍵            | 用途                                                |
|---------------+-----------------------------------------------------|
| ~C-c C-c~       | 構建文檔；默認選 LaTeXMk                           |
| ~C-c C-l~       | 顯示編譯輸出                                        |
| ~C-c `~         | 下一個編譯錯誤                                      |
| ~C-c C-v~       | Okular 打開 PDF，SyncTeX 跳到當前源碼位置           |
| ~C-c {~         | CDLaTeX 插入環境                                    |
| ~`~ 再按符號鍵 | CDLaTeX 插入數學符號                                |
| ~'~             | CDLaTeX 修改前一個數學符號                          |
| ~C-<return>~    | 插入當前環境的下一個 item                           |

~TeX-master~ 以 ~dwim~ 管理多文件文檔：先推斷同目錄的根文件，不能確定時詢問，並把答案
記成 file-local variable。RefTeX 使用這個範圍建立跨文件索引：

| 鍵      | 用途                       |
|---------+----------------------------|
| ~C-c =~   | 文檔目錄                   |
| ~C-c (~   | 建立 label                 |
| ~C-c )~   | 插入 reference             |
| ~C-c [~   | 插入 citation              |
| ~C-c &~   | 查看交叉引用的另一端       |

公式渲染由 preview-latex 明確觸發，不在輸入時持續運行；預覽使用 LuaLaTeX 的 DVI 輸出
與 dvipng，不等待完整的 PDF 構建：

| 鍵                    | 用途                         |
|-----------------------+------------------------------|
| ~C-c C-p C-p~           | 預覽或顯示光標處源碼         |
| ~C-c C-p C-r~           | 預覽選區                     |
| ~C-c C-p C-b~           | 預覽當前 buffer              |
| ~C-c C-p C-c C-p~       | 清除光標處預覽               |

~TeX-fold-mode~ 沒有開啓；它只用 overlay 把宏顯示成 Unicode 或縮寫，不是渲染後的數學
公式。

AUCTeX 按每份文檔的 =biblatex= 設置選擇 bibliography 後端，LaTeXMk 會在需要時調用
Biber。全局構建選項保持 =shell-escape= 關閉；minted 等功能只在可信項目的
=.dir-locals.el= 裏設 ~TeX-command-extra-options~。

Okular 的 forward search 已由 AUCTeX 配好；inverse search 需要在 Okular 的 Editor 設置選
Emacs client。本模塊不配置 Org 公式預覽或 Org → LaTeX 導出。詳細理由與 raw LaTeX
模板見 [[file:org/60-lang-latex.org][lang-latex 模塊]]；完整模式命令仍從 ~M-m h m~ 查看。
