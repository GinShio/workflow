*** 語言服務器配置

**** C/C++ (clangd)

clangd 只會自動搜尋 source tree 的祖先目錄。amdvlk 的 compilation database 位於
source tree 外，因此用一個明確的 project-root 對照表傳入
~--compile-commands-dir~。目前選 release build，因為 debug build 缺少生成的
=lgc/LgcDialect.h.inc=，會令 clangd 在檔案前段停止語意分析。

#+begin_src emacs-lisp
(defvar +lsp-clangd-compilation-database-alist
  `((,(expand-file-name "~/Projects/amd/amdvlk/icd/api/compiler/")
     . ,(expand-file-name
          "~/Projects/amd/amdvlk/_build/amd_stg_llpc-release/")))
  "Map project roots to out-of-tree clangd compilation databases.")

(defun +lsp-clangd-compilation-database-dir ()
  "Return the configured compilation database for the current project."
  (let ((root (file-name-as-directory (expand-file-name default-directory))))
    (cl-loop for (configured-root . configured-dir)
             in +lsp-clangd-compilation-database-alist
             for project-root = (file-name-as-directory
                                 (expand-file-name configured-root))
             for database-dir = (file-name-as-directory
                                  (expand-file-name configured-dir))
             when (and (or (equal root project-root)
                           (file-in-directory-p root project-root))
                       (file-readable-p
                        (expand-file-name "compile_commands.json"
                                          database-dir)))
             return database-dir)))

(defun +lsp-clangd-contact ()
  "Build the clangd command for the current Eglot project."
  (append
   `("clangd"
     ,(format "-j=%d" (max 2 (/ (num-processors) 2)))
     "--clang-tidy"
     "--header-insertion=iwyu"
     "--completion-style=detailed"
     "--pch-storage=memory")
   (when-let ((database-dir (+lsp-clangd-compilation-database-dir)))
     (list (concat "--compile-commands-dir=" database-dir)))))

(set-eglot-client! '(c-mode c-ts-mode c++-mode c++-ts-mode objc-mode)
  #'+lsp-clangd-contact)
#+end_src

*** 結構化編輯 (Combobulate)

[[https://github.com/mickeynp/combobulate][Combobulate]] 是基於 tree-sitter 的結構化編輯工具。
核心功能：

- *語法感知導航*: 按 AST 節點跳轉，比按字符/行高效
- *逐層展選*: 從光標位置逐層擴展選擇到父節點
- *節點拖拽*: 上下移動整個語法節點 (如函數、參數)
- *Envelope*: 快速將選中代碼包裹在 if/for/try 等結構中

*** 快捷鍵總結

整合後的常用快捷鍵：

**** LSP (eglot)
- ~C-c c a~ — 代碼操作 (code actions)
- ~C-c c d~ / ~M-.~ — 跳轉到定義
- ~C-c c D~ / ~M-?~ — 查找引用
- ~C-c c i~ — 查找 implementation
- ~C-c c j~ — 跳轉到 declaration
- ~C-c c J~ — 搜索 workspace symbols
- ~C-c c r~ — 重命名符號
- ~C-c c I~ — 切換 inlay hints
- ~C-c c x~ / ~C-c c X~ — buffer / project 診斷
- ~M-TAB~ — 手動觸發 Corfu/Eglot 補全

**** Tree-sitter + Combobulate
- ~C-M-a / C-M-e~ — 跳轉到函數開始/結束
- ~C-c o n / p~ — 跳轉到同級節點
- ~C-c o u / d~ — 跳轉到上/下層節點
- ~C-c o U / D~ — 拖拽節點上/下移
- ~C-c o h~ — 逐層擴展選擇 (很實用！)
- ~C-c o e~ — 包裹代碼在結構中
- ~C-c o t~ — 使用 avy 跳轉到可見節點

**** DAP (dape)
- ~C-c d d~ — 選擇配置並開始調試
- ~C-c d b~ — 切換斷點
- ~C-c d n / i / o~ — 下一步 / 步入 / 步出
- ~C-c d c~ — 繼續執行
- ~C-c d e~ — 計算表達式

*** 最佳實踐建議

1. **項目配置**：在項目根目錄創建 ~compile_commands.json~ (C/C++) 或對應的
   項目配置文件，讓 LSP 能正確理解項目結構

2. **性能調優**：
   - 大型項目：減少 ~-j~ 參數值 (clangd 並行度)
   - 內存受限：使用 ~--pch-storage=disk~ 代替 ~memory~
   - 減少不必要的診斷：調整 LSP server 配置

3. **漸進式采用**：
   - 先熟悉基本的 LSP 功能 (跳轉、補全、診斷)
   - 再學習 tree-sitter 結構化編輯 (逐層選擇、拖拽)
   - 最後掌握 DAP 調試工作流

4. **語言特定優化**：
   - C/C++：確保有 ~compile_commands.json~
   - Rust：使用 ~rust-analyzer~ 的 clippy 檢查
   - Python：配置 ~pyright~ 或 ~pylsp~ 的 type checking 級別
