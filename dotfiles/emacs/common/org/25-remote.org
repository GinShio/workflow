* 遠程

TRAMP 的想法很簡單：文件名前面加一段前綴，這個文件就在別的機器上。=/ssh:box:/etc/
hosts= 是一個可以 ~find-file~ 的路徑，打開之後它是一個普通緩衝區，保存時寫回那台機
器。編譯、搜索、dired、版本控制都跟着走過去。

代價寫在名字裏——每一次「訪問文件」都變成一次網絡往返。所以這個模塊裏的設置多數是同
一件事的不同側面：讓 Emacs 少問幾次。

TRAMP 的 method、multi-hop、連接屬性與除錯方式見 [[info:tramp#Top][TRAMP manual]]。日常路徑前綴、提權與
清理連接的入口整理在 [[file:../GUIDE.org::*TRAMP][GUIDE.org]]；遇到卡住的遠程操作時，先讀
[[info:tramp#Frequently Asked Questions][TRAMP FAQ]] 再提高 verbose level。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el" :comments no
;;; ginshio-remote.el --- files on other machines -*- lexical-binding: t; -*-
#+end_src

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(require 'ginshio-path)
(require 'ginshio-doctor)
(require 'ginshio-keys)
(require 'files-x)

(autoload 'tramp-cleanup-this-connection "tramp-cmds" nil t)
(autoload 'tramp-cleanup-all-connections "tramp-cmds" nil t)
(autoload 'tramp-cleanup-all-buffers "tramp-cmds" nil t)
#+end_src

TRAMP 自己不在這裏加載。它是內建包裏最大的幾個之一，而多數 Emacs 會話從頭到尾不碰一個
遠程文件；真要碰的時候不需要幫忙——遠程路徑的處理函數是自動加載的，打進一個 =/ssh:= 開
頭的文件名，TRAMP 自己就進來了。

上面三個清理命令是例外。它們的 autoload 住在 =tramp-loaddefs.el=，而那個文件由
=tramp-compat= 在 TRAMP 加載時纔拉起——在此之前，這三個名字在 Emacs 裏不存在；
~declare-function~ 只把這個事實記給編譯器看，不產生任何可調用的東西。綁在 leader 上的
是鍵，鍵不會替你去加載文件，所以在這裏顯式聲明 autoload，讓按鍵在任何會話裏都成立。

於是下面幾乎所有變量都是在 TRAMP 還沒加載的時候賦的值。這是可以的：它們都是
~defcustom~，而 ~defcustom~ 不會覆蓋一個已經有值的變量。反過來就不行——~defvar~ 帶初值
的那些變量必須等它加載之後再動，否則你的賦值會讓它跳過自己的默認定義。本模塊只有一處
碰到這種情況，寫在下面。

** 安靜一點

出廠的囉嗦程度是為調試連接問題準備的，日常使用時它把 echo area 佔滿了握手過程。降下
來之後真正的錯誤才看得見。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(setq tramp-verbose 1)
#+end_src

** 連接復用交給 ssh

TRAMP 默認自己往 ssh 命令行上加一組連接復用選項。這在沒有配置過 ssh 的機器上是好事，
在配置過的機器上是壞事——它用的 socket 路徑和 =~/.ssh/config= 裏那組不是同一個，於是
你精心設置的長連接被繞開，每開一個文件重新握手一次。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(setq tramp-use-connection-share nil)
#+end_src

也就是說連接怎麼復用、活多久，全部由 ssh 自己的配置決定，和你在終端裏 ssh 過去時是
同一套行為。

** 遠程那頭用哪個 shell

本地那個決定寫在 shell 模塊裏：Emacs 拼的命令行交給 POSIX shell，不交給登錄 shell。
遠程這頭 TRAMP 默認就是這麼做的——它不管那台機器的登錄 shell 是什麼，一律要一個
=/bin/sh=。所以遠程主機上裝着什麼交互 shell 都不影響。

** 少問幾次

遠程文件的屬性——存在嗎、多大、什麼時候改的——每問一次是一趟往返，而一次按鍵可能觸發
好幾問。緩存把重複的問題壓掉。

放寬緩存的代價是：別人在那台機器上改了文件，你這邊要晚一點才看見。這是個真實的取捨，
不是白撿的加速。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(setq remote-file-name-inhibit-cache 60)
#+end_src

自動重讀不跟到遠程去。core 打開了全局自動重讀，如果它把遠程緩衝區也算進去，就成了一
個按秒計的輪詢器,每一輪都是網絡往返。這裏把它明確關上，而不是依賴默認值——core 那邊
是全局開啓，兩處放在一起看才說得通。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(setq auto-revert-remote-files nil)
#+end_src

兩台遠程主機之間複製時，讓它們直接對接，而不是把數據拉到本地再推回去。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(setq tramp-use-scp-direct-remote-copying t)
#+end_src

** 版本控制不跟過去

打開任何文件時 Emacs 都會問一句它歸哪個版本控制系統管、當前是什麼狀態。本地這是幾次
文件系統調用；遠程這是幾次 ssh 往返，而且發生在你打開文件和看到內容之間。

這份配置裏版本控制的分工本來就偏向終端——遠程倉庫的操作在那台機器上用 git 做，比隔着
網絡驅動一個 Emacs 前端合理。

不能把 TRAMP regexp 塞進 ~vc-ignore-dir-regexp~：~project.el~ 也把那個變量當成向上尋找
project root 的停止條件，結果是爲了關掉 VC status，連遠程 project、compile 與 Eglot
一起關掉。攔截只放在 VC 刷新邊界，project discovery 仍可使用遠端 Git root。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(defun ginshio-remote-skip-vc-refresh-a (refresh &rest arguments)
  "Skip automatic VC status work for remote buffers."
  (unless (file-remote-p default-directory)
    (apply refresh arguments)))

(advice-add 'vc-refresh-state :around #'ginshio-remote-skip-vc-refresh-a)
#+end_src

** 遠程的目錄列表

file 模塊給 =ls= 的那串開關用了三個 GNU 擴展。遠程列目錄執行的是那台機器上的 =ls=，
它可能是 BusyBox，也可能是 BSD 的——那時整個 dired 打不開，錯誤是一句選項無法識別。

連接局部變量正是為這種情形存在的：同一個變量，在遠程連接上取另一個值。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(connection-local-set-profile-variables
 'ginshio-remote-listing
 '((dired-listing-switches . "-Ahl")))

(connection-local-set-profiles
 '(:application tramp) 'ginshio-remote-listing)
#+end_src

** 提權

改一個 root 擁有的文件，不必退出去 =sudoedit=。=/sudo::= 前綴讓 TRAMP 用 sudo 打開
它，你照常編輯照常保存。

已經在遠程的文件要多想一步：提權必須發生在那台機器上，不是這台。TRAMP 的多跳語法表
達的就是這件事——先按原來的方式連過去，再在那頭切成 root。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(defun ginshio-remote--as-root (file)
  "Return the name under which FILE can be edited with root's permissions.
A file that is already remote gains a second hop rather than a new
connection, so that the switch to root happens on the host holding the
file instead of on this one."
  (if-let* ((prefix (file-remote-p file)))
      (concat (substring prefix 0 -1)
              "|sudo:" (file-remote-p file 'host) ":"
              (file-remote-p file 'localname))
    (concat "/sudo::" file)))

(defun ginshio/find-file-as-root ()
  "Visit what this buffer is showing again, with root's permissions."
  (interactive)
  (let ((file (or buffer-file-name
                  (and (derived-mode-p 'dired-mode) default-directory))))
    (unless file
      (user-error "This buffer is showing neither a file nor a directory"))
    (find-file (ginshio-remote--as-root file))))
#+end_src

** 容器

容器也是「另一台機器」的一種，而且是最常碰到的那種。加載之後 =/podman:name:= 和
=/docker:name:= 和 =/ssh:host:= 用起來沒有區別，容器名字還能補全。

跟着 TRAMP 一起來，而不是自己把 TRAMP 拉起來——它本來就要求 TRAMP 在場，單獨提前加載只
是換一個地方付同一筆錢。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(with-eval-after-load 'tramp
  (require 'tramp-container nil t))
#+end_src

允許加載失敗：這是一個純粹的擴展，缺了它其餘部分照常工作。

** 收拾

連接會卡住——網絡斷了、對面重啓了、sudo 的憑據過期了。症狀是 Emacs 在某個遠程路徑上
沒有反應。斷開那條連接是唯一的辦法，下次訪問時它會重新建立。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-remote.el"
(ginshio-leader-define
 "r"   "remote"
 "r s" #'ginshio/find-file-as-root
 "r k" #'tramp-cleanup-this-connection
 "r K" #'tramp-cleanup-all-connections
 "r b" #'tramp-cleanup-all-buffers)
#+end_src

| 鍵         | 做什麼                               |
|------------+--------------------------------------|
| ~M-m f f~    | 前綴打進去就是遠程路徑               |
| ~M-m r s~    | 把當前文件或目錄用 root 重新打開     |
| ~M-m r k~    | 斷開這個緩衝區用的連接               |
| ~M-m r K~    | 斷開全部連接                         |
| ~M-m r b~    | 斷開全部連接，並關掉它們的緩衝區     |

常用的前綴：=/ssh:host:=、=/sudo::=、=/podman:name:=、=/ssh:host|sudo:host:=。主機名
從 =~/.ssh/config= 補全。
