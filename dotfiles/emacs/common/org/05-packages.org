* 包管理

Emacs 自帶的包管理器只認發布到 ELPA 的版本，而 Emacs 生態裏大量有價值的東西直接活
在 git 倉庫裏，作者也常常按倉庫而不是按發布來迭代。所以這裏換一個能直接從源碼倉庫
安裝的管理器：[[https://github.com/radian-software/straight.el][straight.el]]。它同步地克隆和構建、直接以 commit 鎖定 git 倉庫。

但 straight 在這份配置裏只是一個 *構建工具*，不是配置的一部分。它住在
=maintain.el= 裏，那是一個獨立程序，跟 =tangle.el= 平級。普通 Emacs 啓動不載入它一行。

** 兩個方向都不越界

這條邊界有兩面，兩面都是硬的：

*啓動不碰包管理。* 下載、更新、構建與寫鎖全部由 =bin/ginshio-emacs= 在批處理進程裏
完成。運行中的編輯器不改寫自己的地基，它只讀 =sync= 留下的 activation 快照。缺快照、
缺鎖、或者宣告與快照對不上，立即報錯，不嘗試聯網修復。

*維護不碰配置。* =maintain.el= 從不 ~load~ 任何模塊。它把 =modules/ginshio/*.el=
當作 *資料* ~read~ 進來，從中取出 ~:straight~ 宣告。所以 ~:init~、~:config~ 以及任何
其他配置代碼在維護進程裏都是惰性的文本。

第二條的理由值得說清楚。~use-package~ 是宏，展開後 ~:init~ 是無條件內聯的，而
~:demand t~ 會把 ~:config~ 從 ~eval-after-load~ 裏拉出來變成一句字面的 ~require~。
只要維護進程 ~load~ 了模塊，這些就都跑了——過去它真的會在 =sync= 途中載入主題、打開
全局模式。後果是一個寫壞的 ~:config~ 會讓 =sync= 本身失敗，於是你沒辦法 sync 出那個
坑。讀而不求值把這種可能性整個拿掉了。

** 讀取的契約

recipe 兩邊都不求值：~use-package~ 把源碼形式原樣交給 normalizer，兩邊再原樣交給
straight。所以 recipe 寫成什麼樣就是什麼樣，兩邊 *看到的* 不可能不同——唯一的失效方式
是有一份宣告其中一邊看不見。契約因此只有兩條，而且都會報錯：

- ~use-package~ 必須在文件頂層。嵌在 ~when~ 之類的 form 裏，讀取看得見而啓動不一定執行。
- 不在 ~ginshio-modules~ 裏的支援檔案（如 =ginshio-doctor.el=）不得宣告包。那種文件不在
  讀取的走訪範圍內，快照會少一個包。

還有一處容易寫錯而不是違約：~use-package~ 會把一個關鍵字到下一個關鍵字之間的 *所有*
form 都收成參數，所以 ~:straight a b~ 是兩條 recipe。讀取側照同樣規則掃描，而不是
~plist-get~ 只取第一個。

另一道保險在啓動側：啓動確實會求值模塊，~:straight~ handler 在那時記錄同一份宣告，
=init.el= 結束前拿它跟快照比對。兩邊對不上就是啓動錯誤。

** 命令

| 命令       | 做什麼                                                     |
|------------+------------------------------------------------------------|
| =sync=       | 按鎖安裝缺的包，既有 pin 不動；新增的追加、移除的清掉      |
| =upgrade=    | 拉上游、重建動過的包、把新 revision 全量寫回鎖             |
| =rebuild=    | 按鎖重新構建每一個包                                       |
| =clean=      | 刪 tangle 產物、構建、快照與 native-comp cache；保留 clone |
| =cleanall=   | 再加上 clone                                               |
| =doctor=     | 報告配置需要卻找不到的東西                                 |

=sync= 只在需要時動網路：所有 repo 都已停在鎖定的 commit 時，它一次網路請求都不發。
=rebuild= 存在的理由是 ~straight-check-for-modifications~ 被關掉了，straight 因此從
不自己判斷某個 build 過期；而 =sync= 只重建 revision 真的動過的包，所以「依賴改了宏、
使用它的包卻沒重建」這類殘餘要由 =rebuild= 收尾。它也走 straight 完整的規範化 checkout，
順手修正跑偏的分支與 remote。

換過 Emacs 版本 *不* 需要 =rebuild=：構建目錄按版本分家（見下），新版本的 build cache
是空的，=sync= 自然全建。

* 快照契約

維護進程寫快照、啓動進程讀快照。兩邊必須對「快照長什麼樣」有完全一致的理解，所以那份
理解只寫一次，放在這裏，由兩邊各自 ~load~。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-manifest.el" :comments no
;;; ginshio-manifest.el --- what maintenance writes and startup reads -*- lexical-binding: t; -*-
#+end_src

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-manifest.el"
(require 'ginshio-path)
#+end_src

包樹裝在 =$XDG_DATA_HOME/emacs/= 之下。按「丟了損失什麼」的標準它其實接近緩存——刪掉
只是要重新下載——但自動清理緩存的規則不該有能力讓你的編輯器下次啓動花十分鐘重建。

快照按 Emacs 版本命名，構建目錄也是。字節碼不跨版本通用，而 straight 只在 recipe 變了
或構建缺失時重建，永遠不會因為「跑它的 Emacs 換了」而重建。按版本分家把這件事從「使用
者要記得重建」變成「新版本的 build cache 是空的」，並且讓兩個版本共用同一棵 clone 與同
一份鎖：換回去不用重建。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-manifest.el"
(defconst ginshio-manifest-lock-file
  (expand-file-name "straight.lock" ginshio-config-dir)
  "Pinned revisions, tracked in this repository.")

(defconst ginshio-manifest-tree-dir
  (expand-file-name "straight/" ginshio-data-dir)
  "The package tree.  `maintain.el' reaches it through `straight-base-dir',
which appends this same `straight/' component to the data directory.")

(defconst ginshio-manifest-source
  (expand-file-name (format "activation-%s.el" emacs-version) ginshio-data-dir)
  "Generated snapshot for this Emacs version, kept for reading.")

(defconst ginshio-manifest-file (concat ginshio-manifest-source "c")
  "Compiled snapshot consumed at startup.")

(defvar ginshio-manifest-packages nil
  "Packages the snapshot installed, sorted.")
(defvar ginshio-manifest-declarations nil
  "The (PACKAGE . RECIPE) cells the snapshot was built from, in load order.")
(defvar ginshio-manifest-lock-hash nil
  "Digest of the lock the snapshot was built from.")
#+end_src

~:straight~ 的值怎麼變成 recipe，是維護進程與啓動進程唯一必須逐字元一致的翻譯。它在
這裏定義一次：~t~ 取包名，符號就是包名，以關鍵字開頭的無名 recipe 補上包名，其餘照原
樣。~nil~ 表示「不安裝」——vendored 或內建。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-manifest.el"
(defun ginshio-manifest-normalize (name value)
  "Return the recipes a single :straight VALUE names for package NAME."
  (cond
   ((null value) nil)
   ((eq value t) (list name))
   ((symbolp value) (list value))
   ((keywordp (car-safe value)) (list (cons name value)))
   ((listp value) (list value))
   (t (list value))))
#+end_src

鎖與快照必須成對。鎖換了而快照沒重建，每個包都還在、都能載入，只是停在舊 revision——
一個不會有任何症狀的錯誤狀態。所以快照記下自己是從哪一份鎖建出來的，啓動時比對 digest。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-manifest.el"
(defun ginshio-manifest-lock-digest ()
  "Return the SHA-256 digest of the lock file, or signal.
`secure-hash' digests a string argument as itself, so the file has to be
read in: passing the name would digest the path and never change."
  (unless (file-readable-p ginshio-manifest-lock-file)
    (error "Package lock is missing; run bin/ginshio-emacs sync"))
  (with-temp-buffer
    (set-buffer-multibyte nil)
    (insert-file-contents-literally ginshio-manifest-lock-file)
    (secure-hash 'sha256 (current-buffer))))

(defun ginshio-manifest-load ()
  "Activate the snapshot the last maintenance run wrote."
  (unless (file-readable-p ginshio-manifest-file)
    (error "No package snapshot for Emacs %s; run bin/ginshio-emacs sync"
           emacs-version))
  (load ginshio-manifest-file nil 'nomessage t)
  (unless (equal (ginshio-manifest-lock-digest) ginshio-manifest-lock-hash)
    (error "Package snapshot is older than %s; run bin/ginshio-emacs sync"
           ginshio-manifest-lock-file)))
#+end_src

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-manifest.el" :comments no

;;; ginshio-manifest.el ends here
#+end_src

* 聲明與延遲

啓動側只做三件事：激活快照、驗證每個宣告都在快照裏、記下宣告供結尾比對。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-packages.el" :comments no
;;; ginshio-packages.el --- the packages this configuration declares -*- lexical-binding: t; -*-
#+end_src

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-packages.el"
(require 'ginshio-path)
(require 'ginshio-doctor)
(require 'ginshio-manifest)
(require 'use-package)

(ginshio-manifest-load)
#+end_src

~use-package~ 的 ~:straight~ 關鍵字由這個模塊自己接管，而不是交給
~straight-use-package-mode~ 的內建整合。原因有二：配置的所有 recipe 都寫在
~:straight~ 的值裏，而 straight 自己的整合走 ~:ensure~，不接受這種寫法；而且普通會話
根本不載 straight，那套整合無從談起。

默認延遲 package body；每個宣告仍須用 ~:hook~、~:commands~、~:mode~ 或 ~:demand~ 明
確說明觸發點。完整 ~:config~ 由 =sync= 結尾的 validate 進程逐一 ~require~ 執行，因此
延遲加載不以漏掉配置錯誤為代價。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-packages.el"
(defvar ginshio-package-declarations nil
  "Recorded (PACKAGE . RECIPE) cells, most recently expanded first.
Read through `ginshio-packages-declarations' for load order.")

(defvar ginshio-package-features nil
  "Features named by the `use-package' forms this session expanded.
A package name and the feature it provides are different names: the
`auctex' package provides `tex'.  Snapshot membership is checked against
the former; `ginshio-packages-require-all' loads the latter.")

(defun ginshio-packages-declarations ()
  "Return the recorded declarations in load order."
  (reverse ginshio-package-declarations))

(defun ginshio-packages--normalize-straight (name _keyword args)
  "Normalize the :straight ARGS of use-package NAME into recipes."
  (mapcan (lambda (arg) (ginshio-manifest-normalize name arg)) args))
#+end_src

宣告記錄的是 recipe 的副本。~straight--convert-recipe~ 用 ~plist-put~ 把默認值補進
recipe，而那是就地追加到調用者傳進去的那張 list 上；記錄活物會讓維護進程寫進快照一份
普通會話永遠複現不出來的、被 straight 展開過的 recipe。維護進程現在不求值模塊，所以這
條路已經走不通了，但這個模塊的輸出仍然要跟 =maintain.el= 讀出來的逐字元相同，副本是那
份相同的前提。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-packages.el"
(defun ginshio-packages--straight-handler (name _keyword arg rest state)
  "Check NAME's normalized :straight ARG against the snapshot.
Then process REST with STATE.  ARG is the normalizer's output: nil for
`:straight nil', otherwise a list of package-name symbols or recipes."
  (unless (memq name ginshio-package-features)
    (push name ginshio-package-features))
  (dolist (recipe arg)
    (when recipe
      (let* ((package (if (consp recipe) (car recipe) recipe))
             (cell (cons package (copy-tree recipe))))
        (unless (member cell ginshio-package-declarations)
          (push cell ginshio-package-declarations))
        (unless (memq package ginshio-manifest-packages)
          (error "Package `%s' is not in the snapshot; run bin/ginshio-emacs sync"
                 package)))))
  (use-package-process-keywords name rest state))

;; Register our :straight handling before any later module expands use-package.
(setq use-package-always-defer t
      use-package-expand-minimally t)
(when (memq :straight use-package-keywords)
  (setq use-package-keywords (remq :straight use-package-keywords)))
(push :straight use-package-keywords)
(defalias 'use-package-normalize/:straight #'ginshio-packages--normalize-straight)
(defalias 'use-package-handler/:straight #'ginshio-packages--straight-handler)
#+end_src

** 收束

所有模塊讀完時 =init.el= 調用 finalizer。逐項比對是必要的：快照的成員檢查只回答「這個
包裝了沒有」，回答不了「這條 recipe 改過沒有」。改一個 =:host= 而包名不變，成員檢查一
聲不吭，而裝在那裏的還是舊倉庫。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-packages.el"
(defun ginshio-packages-finalize ()
  "Fail startup unless the declarations match the active snapshot."
  (unless (equal (ginshio-packages-declarations) ginshio-manifest-declarations)
    (error "Package declarations changed; run bin/ginshio-emacs sync")))
#+end_src

=sync= 最後一步在一個全新的進程裏調用下面這個函數。那個進程從零開始，像普通會話一樣
只消費快照，然後把每個宣告的 feature 都 ~require~ 一遍——延遲的 ~:config~ 因此仍然被
執行過一次。它是「普通啓動會不會成立」這個問題的實際答案，所以必須是獨立進程。

#+begin_src emacs-lisp :tangle "modules/ginshio/ginshio-packages.el"
(defun ginshio-packages-require-all ()
  "Load every declared feature, so deferred `:config' bodies run once."
  (dolist (feature (reverse ginshio-package-features))
    (unless (require feature nil t)
      (error "Could not load feature `%s'" feature))))
#+end_src
