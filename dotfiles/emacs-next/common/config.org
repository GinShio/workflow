* 這份配置的取捨

一份手寫的 Emacs 配置遲早會長到沒人記得住，包括作者本人。真正決定它能活多久的不是
寫得多好，而是三年後你還能不能快速回答「這行為什麼在這裏」。所以這裏用文學編程：
散文是主體，代碼是散文的產物。

四條貫穿始終的規則：

*地基不依賴任何第三方包。* 加載順序上排在包管理器之前的模塊，只使用 Emacs 內建設施。
代價是這些模塊寫起來稍微囉嗦；回報是 tangle、smoke test 與 package bootstrap 可以在
套件尚未激活時運行。這不表示普通啓動會容忍殘缺的包樹——完整配置缺一塊就立即失敗。

*配置只有完整成立和啓動失敗兩種狀態。* 模塊錯誤不捕獲，套件的構建與 ~:config~ 錯誤也
必須在 =init.el= 結束前拋出。半份配置帶着已執行的副作用繼續運行，比一個直接的 backtrace
更難修。

*運行中的 Emacs 只消費套件。* 下載、更新、構建與寫鎖由 =bin/vanilla-emacs= 在獨立批處理進程
裏完成；普通會話裏 Elpaca 的變更命令被拒絕。編輯器不在工作途中改寫自己的地基。

*生成物不進版本控制，而且有明確的銷毀邊界。* tangle 產物與套件樹都可由
=bin/vanilla-emacs clean= 整體刪除，再由 =sync= 重建；文學源碼、lock 與使用者資料不在
這條邊界內。tangle 模塊只住在 =lisp/ginshio/=；其他 =lisp/= 子目錄是受版本控制的上游
source，不在清理邊界內。其餘運行時狀態按性質分流到 XDG 目錄。

| =doctor=       | 環境自檢                             | 否           |

| =edit=         | 撤銷歷史、空白與換行、一次改多個地方 | 是           |

| =lang-latex=   | LaTeX：編輯、引用、構建、PDF 同步    | 是           |

| =meson=        | Meson 構建文件：編輯、補全、Eldoc    | 是           |

=path= 由 =bootstrap= 生成，=doctor= 是只供其他模塊 ~require~ 的 =support=；兩者都不進
~ginshio-modules~。其餘模塊由 tangle 按文件名生成清單。

功能模塊往 leader 樹上掛自己的分支，不回頭改 =keys=。=w= 與 =p= 屬於 =window=，
=i= 屬於 =minibuffer=，=e= 屬於 =edit=，=!= 屬於 =shell=，=r= 屬於 =remote=，
=c= 屬於 =lsp=，=z= 屬於 =lang=，=g= 屬於 =vc=，=d= 屬於 =dap=；把一個模塊的 metadata
改成 =disabled=，它的鍵位隨之消失。

=file= 是唯一的例外：它往 =keys= 已有的 =f= 上補兩個鍵，而不是另開一支。它做的正是
「文件」，分家只會讓同一類事住在兩個前綴底下。

每個 =org/NN-name.org= 都以一行 metadata 開頭：

#+begin_example
#+GINSHIO_MODULE: enabled
#+end_example

值只有 =bootstrap=、=support=、=enabled= 與 =disabled=。tangle 直接列出 =org/*.org=，
按完整文件名字典序排序，再從文件名取得 module 名；沒有第二份手寫順序。=enabled= 會被
include、tangle 並加入 ~ginshio-modules~，=disabled= 三者都不做，舊生成檔也在成功 tangle
後刪除。=bootstrap= 與 =support= 始終 tangle，但不加入運行時清單。

所以文件名就是加載順序。數字仍可留白或共用；共用編號時由 =name= 的字典序決定。排序必須
讓 =packages= 位於所有第三方包模塊之前，也必須讓被直接 ~require~ 的模塊排在使用者之前。

最後一段每個文件是一種語言，或一組共享同一用途的格式。有 tree-sitter/LSP 能力的語言只
向框架註冊，框架不認識任何具體語言；llvm-project 自帶的純 Lisp modes 則由 =lang-llvm=
從受版本控制的 snapshot 接入。Markdown、reST 與 AsciiDoc 這類文檔標記共用一個模塊。
三者都保持同一條邊界：增加一類支持只新增一個配置文件，停用時只改自己的 metadata。
CMake 與 Meson 文件排在語言之後，只負責描述構建的文本；真正的項目、branch 與 backend
仍由 Wits 決定。

* 原樣文本

Emacs Lisp 沒有 raw string。把 LaTeX 直接塞進字符串會吃掉單個反斜線，手動改成雙反斜線
又讓原文不能直接複製、編譯或用 LaTeX mode 編輯。LaTeX 因此保持在具名 source block 裏，
tangle 時才把整塊內容打印成合法的 Elisp 字符串字面量。

全局的 =:eval no= 仍然成立；下面是唯一允許求值的 block。它只讀另一個 source block 的
文字，不執行其中內容。使用處還必須明確寫 =:noweb yes :noweb-prefix no=；後者避免 Org 把
引用位置前面的 Elisp 逐行加到多行 LaTeX 上。

#+name: ginshio-source-string
#+begin_src emacs-lisp :var name="" :eval yes :tangle no
(let ((position (org-babel-find-named-block name)))
  (unless position
    (error "No source block named %S" name))
  (org-with-point-at position
    (format "%S"
            (string-remove-suffix
             "\n" (org-element-property :value (org-element-at-point))))))
#+end_src
