** 字體

四種字體各有分工：等寬字體承擔絕大部分工作；比例字體用於閱讀為主的緩衝區；襯線體用
於引文一類需要與正文區分的內容；還需要一個覆蓋面廣的字體兜底那些前三者沒有的符號，
否則它們會顯示成方框。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(defconst ginshio-font-fixed "Fira Mono")
(defconst ginshio-font-fixed-size 15)
(defconst ginshio-font-variable "SourceCodeVF")
(defconst ginshio-font-serif "Source Serif 4")
(defconst ginshio-font-unicode "JuliaMono")
(defconst ginshio-font-cjk "Source Han Mono SC")
#+end_src

等寬字體是 Fira Mono 而不是同門的 Fira Code。兩者字形一致，區別只在後者多了一組編程
連字——把 ~->~ 畫成一個箭頭那一類。在字體這一層把它排除掉，比裝上再關掉省事：沒有哪
個開關需要記得它此刻是開還是關。

另一半在 Emacs 這邊：它不會自作主張把幾個字符併成一個字形。連字要靠顯式登記的合成規
則，通常由一個專門的包完成，而這份配置沒有裝。所以即便哪天換成帶連字的字體，屏幕上
也不會出現箭頭。

漢字字號取西文的 =1.2= 倍，使一個漢字恰好佔兩個西文字符的寬度。這不是美觀問題而是對
齊問題：表格、註釋縮進、以及任何按列排版的內容，都建立在「中文字符寬度是西文的整數
倍」這個假設上。西文字號選 =5= 的倍數可以讓這個乘積落在整數上。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(defconst ginshio-font-cjk-scale 1.2)
#+end_src

字體必須在有圖形 frame 時才能套用，而 frame 何時出現並不確定：常規啓動時它已經存在，
以守護進程方式啓動時則要等到第一個客戶端連上來。因此把套用動作掛在兩個時機上，並讓
它對終端 frame 直接跳過——終端下字體由終端模擬器決定，不歸 Emacs 管。

缺字體不應該讓配置報錯，只是退回到系統默認；缺什麼由自檢負責告知。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(defun ginshio-theme--font-exists-p (family)
  (and family (display-graphic-p) (find-font (font-spec :family family))))

(defun ginshio-theme-apply-fonts-h (&rest _)
  "Apply the configured fonts, if this frame can show them."
  (when (display-graphic-p)
    (when (ginshio-theme--font-exists-p ginshio-font-fixed)
      (let ((spec (font-spec :family ginshio-font-fixed :size ginshio-font-fixed-size)))
        (set-face-attribute 'default nil :font spec)
        (set-face-attribute 'fixed-pitch nil :font spec)))
    (when (ginshio-theme--font-exists-p ginshio-font-variable)
      (set-face-attribute 'variable-pitch nil
                          :font (font-spec :family ginshio-font-variable
                                           :size ginshio-font-fixed-size)))
    (when (ginshio-theme--font-exists-p ginshio-font-serif)
      (set-face-attribute 'fixed-pitch-serif nil
                          :font (font-spec :family ginshio-font-serif
                                           :size ginshio-font-fixed-size)))
    (when (ginshio-theme--font-exists-p ginshio-font-unicode)
      (set-fontset-font t 'symbol (font-spec :family ginshio-font-unicode) nil 'append))
    (when (ginshio-theme--font-exists-p ginshio-font-cjk)
      (dolist (charset '(kana han bopomofo cjk-misc))
        (set-fontset-font t charset (font-spec :family ginshio-font-cjk)))
      (add-to-list 'face-font-rescale-alist
                   (cons ginshio-font-cjk ginshio-font-cjk-scale)))))
#+end_src

** frame

光標不閃。閃爍是持續的動態變化，在餘光裏一直被感知為「有東西在動」。

當前行高亮在兩種緩衝區裏有用：代碼裏跳轉之後一眼找回光標，以及按行選擇的那些
——dired、ibuffer、occur 與 grep 的結果——看清自己停在哪一行。散文緩衝區裏它只是一
條橫貫屏幕的色帶，所以和行號一樣按模式開。

高亮跟着緩衝區，不跟着焦點。~hl-line-sticky-flag~ 關掉會讓它只畫在當前窗口，並且每
次切換緩衝區時刪掉上一個的——當焦點指示器用是够了，代價是這條橫貫屏幕的色帶不停地消
失又出現，比它本來要解決的問題更引人注意。留默認值，它就一直待在那兒。

代價寫在同一枚硬幣的背面：同一個緩衝區開在兩個窗口時，兩邊都畫，而且畫在緩衝區的
point 上——那個位置未必是非選中窗口自己的光標所在。

dired 要單獨掛一次：它比 ~special-mode~ 出現得早，至今沒有從它派生。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(add-hook 'prog-mode-hook #'hl-line-mode)
(add-hook 'special-mode-hook #'hl-line-mode)
(add-hook 'dired-mode-hook #'hl-line-mode)
#+end_src

透明背景在兩種環境下走不同的路。圖形界面由 Emacs 自己合成；終端裏沒有這個能力，唯一
的辦法是拒絕繪製背景，露出終端模擬器自己的背景。

後者有個副作用值得知道：加載主題會重繪默認 face，把不繪製背景這件事覆蓋掉。所以這個
動作必須在每次主題切換之後重新執行一遍。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(defconst ginshio-frame-alpha 96)

(defun ginshio-theme-apply-frame-h (&rest _)
  "Apply appearance that theme loading or frame creation would otherwise reset."
  (let ((frame (selected-frame)))
    (if (display-graphic-p frame)
        (set-frame-parameter frame 'alpha-background ginshio-frame-alpha)
      (set-face-background 'default "unspecified-bg" frame))))
#+end_src

窗口標題顯示緩衝區名，有項目時附上項目名。

項目名必須緩存。標題裏的求值表達式在 *每次重繪* 時執行，而判斷當前項目要沿目錄樹向上
逐級查找版本控制標記——那是一連串文件系統調用。不緩存的話，編輯遠程文件時每次重繪都
會變成一次網絡往返。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(defvar-local ginshio-theme--project-name 'unset)

(defun ginshio-theme-project-name ()
  "Return the current project's name in brackets, or an empty string."
  (when (eq ginshio-theme--project-name 'unset)
    (setq ginshio-theme--project-name
          (when-let* ((project (project-current nil)))
            (project-name project))))
  (if ginshio-theme--project-name
      (format "  -  [%s]" ginshio-theme--project-name)
    ""))

(setq frame-title-format
      '("%b – GNU Emacs" (:eval (ginshio-theme-project-name))))
#+end_src

** 代碼裏的註記

=TODO= =FIXME= =HACK= 這類詞寫在註釋裏，而註釋整體是暗的。寫下的那一刻你知道它在那；
兩週後掃過同一屏代碼，它和周圍的散文一個顏色。[[https://github.com/tarsius/hl-todo][hl-todo]] 把它們從註釋的顏色裏拎出來。

顏色給的是 face 名字，不是色值。這個包出廠帶一組十六進制顏色，換一個主題就可能和背
景撞到看不清；~error~ ~warning~ ~success~ 由主題自己定義，跟着主題走，而它們表達的
輕重正好對得上這幾類註記。

只分三檔：要修的、要當心的、只是說明的。再細下去就變成了給自己出分類題——站在一行註
釋前猶豫該寫 =HACK= 還是 =KLUDGE=，那一刻損失的注意力比這個標記將來省下的多。

它默認不進 org。那裏的 =TODO= 是 org 自己的待辦狀態，已經有顏色，也已經有含義。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(use-package hl-todo
  :ensure t
  :init
  (setq hl-todo-keyword-faces
        '(("TODO"       . error)
          ("FIXME"      . error)
          ("BUG"        . error)
          ("XXX"        . error)
          ("HACK"       . warning)
          ("REVIEW"     . warning)
          ("DEPRECATED" . warning)
          ("NOTE"       . success)))
  :hook ((prog-mode conf-mode) . hl-todo-mode))
#+end_src

(defun ginshio-theme-nyan-visible-p ()
  "Return non-nil when a focused graphical frame can display Nyan."
  (seq-some (lambda (frame)
              (and (display-graphic-p frame)
                   (frame-visible-p frame)
                   (frame-focus-state frame)))
            (frame-list)))

        (nyan-start-animation)
      (nyan-stop-animation))))

** 啓動畫面

默認的啓動畫面是一份指向 GNU 文檔的鏈接列表，看過一次就不再需要。它佔著的那一屏可以
拿來回答「上次做到哪了」：最近的文件、最近的項目、存下的書籤。

[[https://github.com/emacs-dashboard/emacs-dashboard][dashboard]] 做這件事。它自己畫橫幅、自己排版、自己在窗口尺寸變化時重繪——最後這條是它
和手寫版本的關鍵差別：手寫版本靠向顯示引擎描述「居中」來迴避尺寸未知的問題，
dashboard 選擇算出空格數，然後在每次窗口變化時重算一遍。兩條路都通，換成包就跟它的路。

*** 橫幅

=banners/= 目錄還是橫幅的來源。dashboard 接受一個 =(圖片 . 文本)= 的組合，圖形界面
用前者、終端用後者——正好對上這個目錄裏 PNG 和 =.txt= 並存的結構。

每次重繪都重新抽一次，所以同一次會話裏開新 frame 也會換一張。目錄空了就交回給
dashboard 自帶的橫幅，不報錯——啓動畫面壞掉不該影響啓動。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(defconst ginshio-banner-dir (expand-file-name "banners/" ginshio-config-dir))

(defun ginshio-banner--random (pattern)
  "Return a random file in the banner directory matching PATTERN."
  (when (file-directory-p ginshio-banner-dir)
    (when-let* ((files (directory-files ginshio-banner-dir t pattern)))
      (seq-random-elt files))))

(defun ginshio-theme-choose-banner ()
  "Pick a banner for the dashboard.
A cons of image and text lets a graphical frame show the image and a
terminal the ASCII file.  With nothing to choose from, the package falls
back to its own."
  (let ((image (ginshio-banner--random "\\.png\\'"))
        (text (ginshio-banner--random "\\.txt\\'")))
    (cond ((and image text) (cons image text))
          (image image)
          (text text)
          (t 'official))))

(defun ginshio-theme-show-dashboard-h (&rest _)
  "Rebuild the dashboard, with a fresh banner, and put it in front."
  (setq dashboard-startup-banner (ginshio-theme-choose-banner))
  (dashboard-refresh-buffer))

(defun ginshio-theme-dashboard-buffer ()
  "Return the dashboard, built and current."
  (require 'dashboard)
  (ginshio-theme-show-dashboard-h)
  (get-buffer dashboard-buffer-name))
#+end_src

**** 有事情做的時候不要畫

被要求打開文件的 Emacs 不該先給你看一屏啓動畫面。而 ~initial-buffer-choice~ 的處理方式
會讓它比「多一個窗口」更糟：那個值指定的緩衝區被 *插到* 待顯示列表的最前面，於是命令行
給了一個文件時列表長度成了二，Emacs 走進「兩個就都顯示」的分支——劈開 frame，然後把焦點
留在啓動畫面上。你要編輯的那個文件在旁邊那半，而光標不在那裏。

`git commit` 正是這條路：它啓動一個新的 Emacs，把 =COMMIT_EDITMSG= 交給它。

修法不是關掉這個變量，而是讓它回答得誠實一點：已經有緩衝區在訪問文件時，就交出那一個。
交回列表裏已經有的緩衝區不會讓列表變長，於是它獨佔 frame 並且拿到焦點——正是 Emacs 沒有
啓動畫面時的行為。

#+begin_src emacs-lisp :tangle "lisp/ginshio/ginshio-theme.el"
(defun ginshio-theme-initial-buffer ()
  "Return the buffer to put in front when Emacs starts.
The dashboard, unless Emacs was told to open a file, in which case that
file has already been visited by the time this runs."
  (if (frame-parameter nil 'client)
      (ginshio-theme-dashboard-buffer)
    (or (seq-find #'buffer-file-name (buffer-list))
        (ginshio-theme-dashboard-buffer))))
#+end_src

*** 什麼時候畫

套件隊列現在在 =init.el= 返回之前完成，所以 ~initial-buffer-choice~ 一定來得及設置，不
需要再用 package 或 server hook 補畫一次。

~emacsclient~ 沒有帶文件、命令或表達式時也會調用 ~initial-buffer-choice~。client frame
以 =client= frame parameter 辨認；這條路永遠返回 dashboard，而不是從長期會話的全域
~buffer-list~ 裏撿到一個舊文件。有文件的 client 不調用這個函數，server 會直接顯示目標。

#+begin_quote
window 模塊在同一個鉤子上恢復上次的會話，排在這之後。有存檔時它會蓋掉這一屏——想保留
啓動畫面就把那邊的 ~desktop-save-mode~ 關掉，兩者回答的是同一個問題。
#+end_quote

*** 鍵位

全部由 ~dashboard-mode-map~ 提供。它是主模式映射，不經過被清空的全域映射，所以出廠鍵
位在這裏原樣可用。

| 鍵          | 做什麼               |
|-------------+----------------------|
| ~n~ ~p~         | 上下移動             |
| ~TAB~         | 跳到下一個條目       |
| ~RET~         | 打開光標所在的條目   |
| ~r~ ~p~ ~m~       | 跳到最近文件 / 項目 / 書籤那一段 |
| ~{~ ~}~         | 上一段 / 下一段      |
| ~g~           | 重畫                 |

** 自檢項

                     :note "the main typeface"
                     :remedy "https://github.com/mozilla/Fira")
(ginshio-doctor-font 'theme ginshio-font-variable
                     :severity 'warn :note "proportional text")
(ginshio-doctor-font 'theme ginshio-font-serif
                     :severity 'warn :note "quotations and headings")
(ginshio-doctor-font 'theme ginshio-font-unicode
                     :note "fallback for uncommon symbols"
                     :remedy "https://juliamono.netlify.app")
(ginshio-doctor-font 'theme ginshio-font-cjk
                     :note "CJK text"
                     :remedy "zypper install adobe-sourcehansans-sc-fonts")

                     :note "icons in the modeline and completion menus"
                     :remedy "M-x nerd-icons-install-fonts")
